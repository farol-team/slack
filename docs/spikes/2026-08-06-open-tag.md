# Spike — "Open Tag": positioning Farol as the open-source Claude Tag

**Date:** 2026-08-06 · **Method:** argument built on two evidence bases — the
official Claude Tag docs and Anthropic engineering posts researched today
(recorded in [docs/claude-tag-comparison.md](../claude-tag-comparison.md)),
and the 25-product survey in
[Slack agent market](2026-08-05-slack-agent-market.md). No new fieldwork;
everything cited below says where it came from.

The question: is *"Claude Tag, but open — any agent, your infrastructure"* a
positioning worth adopting, the way OpenCode positioned itself against Claude
Code?

## Observed (with sources)

**Anthropic is building the category for us.** Tag launched in beta
2026-06-23; legacy Claude in Slack is force-migrated 2026-08-03; launch
credits are $25k/Enterprise org, $2.5k/Team org (support article, read
2026-08-06). The market is being taught, at Anthropic's expense, what an "AI
teammate in a Slack channel" is.

**Tag's gate and limits, from official docs (read 2026-08-06):**

- Team/Enterprise plans only; "isn't available on individual plans (Free,
  Pro, or Max), or for third-party deployments" — docs overview, verbatim.
- Hosted-only: ephemeral sandbox per thread on Anthropic infrastructure; no
  on-prem option.
- Agent Proxy egress is HTTP/HTTPS only — "a protocol that isn't HTTP, such
  as SSH or a database's native wire protocol, can't cross the proxy" —
  agent-identity page, verbatim.
- Claude only; post-beta pricing unannounced; channel usage metered against
  an org-funded balance.

**The open-source shelf is not empty** (market spike, 2026-08-05): OpenHands
is MIT with 83k★, ships Slack on every tier, resells models at cost; Multica
hit 44k★ in seven months with a local daemon and a mention-becomes-issue
flow. Neither is BYOA: OpenHands runs its own agent, Multica its own runtime.

**What Farol already has** (repo, today): BYOA over ACP with two working
adapters (claude-agent-acp, opencode — the OpenCode analogy is literal, not
rhetorical); local execution with zero open ports; HITL Approve/Deny/Stop in
Slack; channel-scoped memory behind a gateway that never hands the agent
credentials — the same pattern Tag's Agent Proxy applies to all egress.

**What Farol does not have** (same comparison doc): shared channel agent —
our mention runs on the *author's* runner only; proactivity (none);
governance (no audit log, no quotas). Tag has all three.

## Concluded (labelled as inference)

**The positioning is legible and rides a paid-for wave.** "Open Tag" needs
one sentence to explain and inherits every objection Tag generates:
Enterprise-gated → works with the Claude subscription a developer already
has; hosted-only → runs inside your perimeter; Claude-only → any ACP agent;
metered → your own agent bill, nothing on top.

**The sharpest wedge is the plan gate.** Every developer on Pro/Max — the
entire individual-subscription audience — *cannot get Tag at any price*.
Farol lets their existing Claude Code subscription answer mentions in Slack
today. That segment is concrete, reachable, and structurally ignored by
Anthropic's own product split (team → Tag, personal → Code).

**The free niche is the protocol layer, not "open agent in Slack".**
OpenHands and Multica already occupy "open source agent you can point at
Slack". Nobody occupies "bring *any* agent to Slack over a standard protocol,
executing behind your perimeter". That framing also matches the market
spike's conclusion: if the runner stays the moat, aim at teams whose work
needs a machine and its credentials (DevOps/SRE, data engineering, internal
tools) — cloud sandboxes with HTTP-only egress cannot reach a database wire
protocol or an SSH host by construction.

**Two preconditions before the name is honest:**

1. **Shared channel agent.** Tag's defining semantic is one agent per channel
   that the whole team steers. Farol's author-bound routing makes us "open
   Claude Code in Slack", not "open Tag". A channel-bound runner mode (Chat
   already lives at thread level; channel bindings exist) is the minimum
   feature to claim the word. Proactivity and governance can follow; this
   cannot.
2. **A deliberate open-core line.** Decide what opens (runner is obvious;
   cloud/ self-host probably; app/ control plane probably not), the licence
   (precedents on the shelf: Multica's Apache-plus-no-hosted-service, n8n's
   fair-code, OpenHands' plain MIT), and what stays paid — hosted control
   plane, governance layer (audit, quotas — which Tag has and we need
   anyway), managed memory. Opening the repo without this line is donating
   the product to OpenHands for review.

**Risks, named:** the name flirts with Anthropic's trademark (OpenCode
precedent suggests tolerated; "tag" is a generic word; risk low, not zero —
`<OpenTag>` reads as a developer pun, which helps). Open-sourcing a product
that executes code from Slack messages raises the security bar: the HITL
buttons and directory allowlist stop being features and become the pitch's
load-bearing wall.

## So what

Adopt the positioning direction, but sequence it: (1) build the shared
channel-agent mode, (2) draw the open-core line and pick the licence, (3)
launch the "Open Tag" framing aimed first at Pro/Max developer teams, second
at behind-the-perimeter ops teams. Until (1) ships, the honest one-liner is
"your coding agent, in Slack, on your machine" — still good, just not yet
"Tag".
