# Spike — Viktor ("hire an AI employee")

**Date:** 2026-08-05 · **Method:** read the public landing, pricing and
security pages (viktor.com). No account, no code — everything below is their
own claim unless marked otherwise.

## What it is

A hosted AI employee that lives in Slack and Microsoft Teams. Installed from
the app directory ("takes 2 minutes"), connects to **3,200+ tools** over OAuth
(Salesforce, HubSpot, Zendesk, Stripe, Notion, Linear, Google/Meta Ads, Gmail),
and returns work products: "PDFs, spreadsheets, web apps, code". Scheduled runs
are a headline feature — "works while you sleep, not just when you ask".

Execution happens in **their** cloud: AWS us-east-1, per-workspace sandbox, EU
residency for enterprise. Models are routed across Anthropic, OpenAI and Google
under no-training/zero-retention agreements. SOC 2 Type 1, Type II in progress.
Memory is called "skills", scoped to the workspace; per-channel disabling and
self-serve deletion of conversations/memory are admin/enterprise features.

Pricing is workspace credits, no per-seat charge: $50 / 20k credits up to
$5,000 / 2M, enterprise $35–50k for 14–20M. They price the work, not the user:
a quick Slack question 50–300 credits, a complex workflow 500–1,500, a full
project 2,000–5,000 — roughly $0.15 for a question and $5–12 for a project.

Marketing numbers on the same page disagree with each other ("13,200+
workspaces", "20,000+ teams"), which is worth remembering before quoting either.

## How it relates to Farol

Same surface — a bot in Slack that is asked to do work. Different substrate:

| | Viktor | Farol |
|---|---|---|
| Where work runs | their AWS sandbox | the developer's own machine |
| Reach | SaaS APIs it holds OAuth for | the real repo, toolchain, VPN, local creds |
| Model | their router, billed as credits | the customer's own agent and subscription |
| Buyer | ops, marketing, sales | engineering |

The structural line: Viktor cannot enter a private repository behind a VPN,
because it has no machine there. We can, and the source never leaves the
developer's laptop — the cloud routes text, not code. That is the one claim of
ours a hosted competitor cannot copy by shipping features.

## Where we look worse

1. **A closed laptop is a dead bot.** BYOA routing needs the author's runner
   online; a hosted employee is always up. This is the difference between a
   tool and a teammate, and it is the first thing a buyer notices.
2. **No proactive work.** They schedule; we only react to a mention. Our
   runner already holds a persistent WS — cron → `assign_turn` is small work
   for a feature that reads as a category difference.
3. **Install cost.** "Two minutes from the app directory" versus a `.dmg` on
   every developer's Mac.
4. **Trust artifacts.** SOC 2 and self-serve memory deletion exist on their
   side. Our channel-scoped gateway is technically stricter and attested by
   nobody.

## So what

- Do not position as "an AI employee in Slack". On that shelf we are the
  cheaper-looking option that takes longer to explain, and the buyer's first
  question becomes "why a second bot". Position on the substrate: Slack as the
  interface to *your* coding agent on *your* machine.
- Their credit pricing is an opening, not a threat: we resell no tokens, so a
  heavy task costs us close to nothing at the margin while it is exactly what
  drains their credits first. Sell per seat/runner and never fear big tasks.
- The real squeeze is not Viktor — it is Claude-in-Slack from one side and the
  IDE/GitHub agents from the other. Against the first we have the machine and
  its access; against the second, the fact that the whole team lives in Slack
  and only one person has the IDE open.
